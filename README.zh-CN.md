## 有什么 / 没有什么

- 有：管理员人工核验过的目录（带核验日期）；可用率与首 token 时间（TTFT）的自动测量，标明节点和统计窗口；方法与限制；目录快照与专题仓链接。
- 没有：实时数据（表格是已发布快照，站点上更新）；跨模型的「总冠军」排名（只比较同一模型）；可用性或资金安全担保（进目录不代表为服务商背书）。

## 怎么比较

- 只比较同一模型：精确 model ID、协议、支付条件、核验日期。
- 「未核实」不等于「没有」；没有价格不等于免费。
- 「接受卡片」与「可用俄罗斯银行卡支付」是两件事；只公开管理员亲自核验过的支付方式。
- 可用率 = 24 小时内成功次数 / 全部尝试；429 与超时都算失败。
- 一次测量或一个可用率数字不能证明模型被替换，也不能证明没被替换；数字指纹是参考库内的排名，不是权重真伪证明。
- 建议先小额充值：今天在表里不保证明天可用。

## 测量时间与地点

- 表格上方始终有快照编号、数据时间（UTC）、测量节点、统计窗口。
- 只从一个节点测；读者自己的网络下延迟与可用率可能不同。
- 自动测量是短请求，不含 tools、提示词缓存与长上下文。

## 站点栏目

比较页、服务商目录、自测（鹈鹕与速度可用；指纹因缺少参考数据尚未接通；Key 不保存）、Claude Code 接入、方法、博客、申请页——全部链到 ru.folkbench.com 的真实路径，不在 GitHub 复制站点功能。

## 目录快照

- 是公开目录快照的副本，不是数据库实时数据；按名称排序，不是排行榜；不按服务商名称剔除行。
- 由 `scripts/ru-readme.mjs` 从 `https://ru.folkbench.com/api/v1/public/catalog` 生成，不手改；更正走申请 / 纠错渠道，由管理员核验后改库。

## 更新方式

- 目录数据在 ru.folkbench.com 数据库里，测量按站点自己的调度进行。
- 本仓表格由 GitHub Actions 单独更新，通常每天一次；快照取不到或格式校验失败时保留上次成功的表格，所以表上时间可能落后于站点。以表上时间为准，不以提交日期为准。
- 历史见提交记录。

## 广告与联盟链接

- 站点收入来自收录费、广告与联盟链接；广告位一律标「Реклама」，不进表格。
- 付费不能改变排序与测量结果；广告主与其他服务商用同一请求、同一节点测量。
- 跳到服务商网站经 `/go/` 中间页，可能带联盟参数（AFF）。
- 本仓库没有广告。
- 详见方法页 `/methodology/#ads`。

## 申请与纠错

- 邮箱 reply@folkbench.com、Telegram @mmmagnus98、本仓两个 Issue 模板。
- 条件、收录价格与审核流程见 `/submit/`；付费收录不影响表格排序。Issue / PR 只是建议，管理员核验来源后写库；测量结果不按要求改，测错了修原因，不改数字。
- 粗体提示：不要在 Issue 里贴 API Key、密码、支付信息或证件。
